# 新建作品单图层与 50 帧上限设计

## 背景

PC 端像素编辑器当前创建空白帧时默认包含两个图层。项目持久化层已经会将帧数裁剪到 50 帧，但编辑器的新增帧、复制帧和 GIF 导入入口没有统一地在操作发生前阻止超限。

## 目标

- 新建作品的首帧默认只有一个空白图层。
- 新增空白帧同样默认只有一个空白图层。
- 历史作品已有的多图层数据保持不变。
- 图层数量下限调整为一个，允许用户将多图层删除至只剩一个图层。
- 单个作品最多包含 50 帧；新增、复制和 GIF 导入均不能突破该上限。

## 方案

核心模块继续以 `MAX_PROJECT_FRAMES = 50` 作为唯一帧数上限。`makeFrame()` 只创建一个图层；`sanitizeProject()` 只为没有图层的异常帧补足一个图层，不删除历史帧中已有的合法图层。

编辑器在新增帧和复制帧前检查当前帧数，达到 50 帧时不修改项目并显示上限提示。GIF 导入在替换或插入前计算导入后的帧数；若会超过 50 帧，整次导入失败并提示，不静默截断。持久化清洗仍保留最多 50 帧的兜底裁剪，以防外部或历史数据异常。

删除图层时仅在当前帧只剩一个图层时阻止删除，从而保证每帧至少有一个可编辑图层。

## 测试

- 核心测试验证 `makeFrame()` 和 `makeProject()` 默认只有一个图层。
- 核心测试验证清洗无图层帧时补足一个图层，并保留合法多图层帧。
- 编辑器契约测试验证新增帧、复制帧和 GIF 导入均引用统一的 50 帧上限并在超限时停止操作。
- 更新 GIF 帧数上限测试，使其与 50 帧规则一致。

## 非目标

- 不迁移或合并历史作品已有图层。
- 不改变每帧最多四个图层的现有规则。
- 不自动截断用户选择导入的 GIF。
